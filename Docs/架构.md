## 1.5 移动规则（10-06 地基重做；设计与过程见 [地基方案](./地基方案.md)）

- **规则层**（walk.js、sim）：他沿路中线、按“从哪个路口到哪个路口”走，门在 `node`—`doorTo` 那段路的 `doorAt` 处；规则快照（simsnap）不受画面影响。
- **可行走地图**（space.js，第 3 层）：“哪里能走”的唯一来源——人行网（路口四角、人行道、过街、各门接入）、门前空地、实体外形（`town.solids`，合并网格前从网格算出）。寻路 `space.path`／`world.roadPath`；`isWalkable`、`canStand`。人行线离路中线 1.9，车道 0.8。
- **统一移动入口**（mover.js，第 3 层）：所有会动的人都经 `stepTo`／`stepAlong` 走——起步平滑、朝向跟着走、**不许“落后多少就快多少”**；过街默认问让行（路口里正在过车就等，并告诉车有人在等）；站在马路上的人先走完。每帧最后 `separate` 把离得太近的人推开（推前看能不能站，不推爷爷）。
- **画面与规则层对齐**（10-06 动法统一）：画面速度＝规则层此刻速度（`sim.walkRate`）×倍速×1.3；画面落后 6 以上或跟着的人掉队，`sim.setVisualLag` 让整个时钟停一下（画面的等待不占游戏时间，模拟与真实游戏结果一致；一次最多 8 秒）；一天收尾等画面里的人都进了家门（`h.visualAtHome`）。
- **爷爷的画面**（actors.js）：在人行线上追规则层的位置（换路段少过街、过街走斑马线、稍靠右、前面有人先慢下来）；人行线上的目标点按规则层在这段路上走到的比例连续移动（不在街角夹住）；速度＝目标点自己的速度＋按落后多少加减，每秒最多变 0.6 倍、目标点停着时按刹得住的速度慢下来（10-07 匀速）；直线走不过去就寻路；进门出门、家里走门口连线。跟随的人（陪同、孙女、健步走队伍）面包屑式沿他画面里的足迹走（只往前、只让排在前面的人；按他此刻的画面速度走，离自己的位置远了稍快、近了稍慢，不再全速追上就停）。家里走到一个位置先站 0.6 秒再去下一处。
- **镜头看得见他**（camera.js `keepInSight`／`seenFrom`，10-08 用户定“调镜头”）：自动跟随时，他大半个身子被亭子顶、棚子、房子挡住 1.5 秒以上，镜头在附近一圈角度里找改动最小、能完全看见的（先放低、再小转，转向代价算两倍，地图朝向尽量不变；每帧试 4 个，不卡），约 1 秒转过去；原来的角度连续 1.5 秒看得见再转回。玩家手指／鼠标按在画面上时（`cam.drag`，按 controls 的 start／end）自动视角和跟随都让开；拖动过就 `releaseSight`，镜头停在玩家拖到的地方、不再转回（10-14：原来松手那一下被拽回自动换角度前的方向，12 次拖转里 9 次）。`seenFrom` 对小镇合并的大网格按地面 4×4 格子只试射线经过的三角形（10-14：原来一次约 2 毫秒、手机上 8—11 毫秒，找角度时连续卡；结果与逐个试相同，`__mg.sightCheck()` 对照）。检查：walkcheck“看不见他”（同一个 seenFrom 口径，连续 3 秒）。
- **路人与车**（ambient.js）：路人在人行网上逛（前面有人按间距减速、0.45 以内才停；快到路口先定下一段，要过街而路口在过车就提前慢下来；挡着爷爷先往右让一步，让不开才掉头；已经在马路上的不停下等车）；车有速度、加速和刹车上限，按“刹得住的距离”定此刻能开多快（对人、对前车、对停车线都一样，曲线按刹车能力的 3/4 留余量），路口空着就不减速直接按转弯速度开过去，只有排在最前（到停车线之间没有车）才占路口；车走车道、停车线、路口一次一车，过路口沿离线验证过的弯线（直行不离车道、不掉头），行人优先（有人在路边等着过街，停车线前的车先让）。每天开始重摆（flow.startDay）。
- **检查**：`tools/walkcheck.mjs`（三种走法×7 天，每 0.1 秒；源码比构建新先重新构建；另有 1×／2×／中途换倍速、随机帮法变体与每天缩略图 `tools/daysheet.mjs`，见第 5 节）——出界、进墙、车穿人、车出路面、车／路人僵住、人叠人、页面报错，以及“动得对不对”：冲刺、横移、掉队、不跟、互相等、画面卡住、顿挫（人速度短暂掉到四成以下又恢复，附每帧原因）、车急刹／急起步、时钟为等画面停的秒数（速度按画面实际走过的帧时间 `run.frameClock` 算，不按真实时间——无头浏览器掉帧会误报）；`__mg.space(true)` 调试画面、`__mg.clearance()`、`__mg.overlaps()`、`__mg.spaceCheck()`。

## 1.6 时间系统（09-26 全局审查后）

**三种“停”，各走各的路，不许混用**

| 哪种停 | 怎么触发 | 时钟 | 声音、世界动画 | 界面 |
|---|---|---|---|---|
| 玩家暂停 | `run.speed = 0`：暂停键、空格、设置、手册、切到后台（只在 `hud.js` 里 `setSpeed(0)`） | 停 | 全停（声音挂起，继续时接着播） | 时钟闪烁 |
| 剧情停顿 | `story.holds`（`core.js`）：讲往事 | 停 | 照常（人物说话、邻居走动） | 时钟变灰、下有短线；点一下界面回来，再点跳过 |
| 关卡、犹豫时刻 | `sim.moment` | 停 | 照常 | 同上 |

- **为什么关卡里时钟停**：小关卡是“把镜头拉近看他做这件事”，不给老人玩家加时间压力；读题、想一想都不扣时间。关卡内部自带的计时（如只看一眼的短信、只说一遍的步骤）是关卡的玩法，与游戏时钟无关。
- **做选择花掉的剧情时间**（等一等 +8 分、提示 +3 分、一起做小关卡 +4 分、闹钟没修好晚出门 +30 分）：只经 `sim.advance(分钟, 原因)` 加，画面在时钟下方显示“+N 分钟”——不让人以为时间偷偷走了。平时的时间只在 `sim.update` 里走。
- **剧情节拍的延时**（孙女跑出来 → 他说“慢点跑” → 讲往事；邻居接话；比赛后镜头复位）用 `later(秒, fn)`：只在玩家没暂停时计时，按下暂停这些也一起停；换一天 `clearLater()`。纯界面的延时（提示淡出、按钮闪烁）照用 `setTimeout`。
- **小关卡与地图示范里按真实时间走的节拍**（对白一句接一句、说完自动收尾、示范的笔）用 `game-kit` 的 `later／every`（底下是 `util.pauseTimeout／pauseInterval`）：玩家暂停时剩余时间冻住，继续后接着计；停掉用 `stop()`。`hud.setSpeed` 暂停时调 `pauseTimers`。讲往事时点顶栏、设置里的按钮不算“点画面跳过”。暂停时只接受顶栏（继续、倍速、菜单）、目标面板、设置／手册的点按，拖动缩放镜头照常；关卡、犹豫面板、地图连线、道具、电话和画面上的点选一律拦下，暂停键闪一下并提示“点继续”（`hud.guardPause`）。`tools/pausecheck.mjs` 检查这些（10-13）。
- **自动快进**只在“没事发生”时（在家等下一件事、在屋里办很久的事）把速度提到某个值，不与玩家倍速相乘；剧情停顿、关卡、犹豫时刻里不快进。
- 检查：`tools/datacheck.mjs` 报出直接给游戏时间加数、在 `hud.js` 以外 `setSpeed(0)`。

## 1.65 事件流（情境系统 S4-1，09-26）

规则层每件事调 `sim.event(种类, 数据)`，存进 `sim.events`（每天清空）并通过回调 `event` 通知画面。每条自动带情境 `sim.ctx()`：第几天、几点、所在路口、去／回（`leg`）、状态（`mode`）、正在办的事（`goal`／`task`／`place`）、目的地名、是否下雨、是否迷路、是否有人陪，以及上一件事（`prev`）。事件只记录，不改规则结果（规则快照不变）。

| 种类 | 什么时候 | 附带 |
|---|---|---|
| `dayStart`／`dayEnd` | 一天开始／结束 | |
| `depart`／`arrive`／`enter`／`home`／`hikePoint` | 出发（定下走哪扇门）／到门口／进门／到家／健步走路过一点 | `gate` |
| `pass` | 走到一个路口 | |
| `hesitate`／`wrongTurn`／`lost`／`found`／`stuck`／`askWay`／`forgetRoute` | 犹豫、拐错、迷路、认出路、停住、问路、记不清指的路 | `changed`、`detour`、`why` |
| `greet`／`neighborHelp`／`encounter` | 邻居打招呼、邻居帮忙、路上偶遇 | `who`、`near`、`encounter` |
| `favor` | 托带的事：想起／忘了／路上交／到家交／到家发现忘了／晚上交 | `state`、`who` |
| `moment`／`choice`／`momentEnd`／`letGo` | 犹豫时刻打开、玩家选择、结束、顺其自然 | `moment`、`choice`、`ok`、`self` |
| `level`／`levelEnd` | 小关卡开始／结束 | `level`、`q` |
| `goalEnd`／`late` | 一件事办完（成／半成／没办成）、迟到 | `goalId`、`status`、`note` |
| `timeJump`／`rain`／`phoneRing` | 时间一下子过去、开始下雨、手机响 | `min`、`why` |
| `memory`／`memoryEnd` | 讲往事开始／结束 | `skipped` |
| `player` | 玩家操作：布置、电话、陪同、暂停、继续、倍速、关卡里点按钮 | `op`、`support`、`speed`、`label` |

- 无头跑一天拿事件流：`node tools/storyrun.mjs 第几天 [玩法] [种子]`（`runDay()` 供自检工具共用，`simsnap` 已改用它）。
- 台词记录（`core.lineLog`）与事件共用同一份情境 `sim.ctx()`。
- 自检：`tools/storycheck.mjs` 按事件流查先后（时间不倒流、首尾、每件事只结束一次、托带前后、到家后没有路上的事、到了门口不判迟到、关卡成对）与台词情境（邻居的话按事件当时的情境挑）。

## 1.7 台词与声音（09-26 第十四轮后；S4 情境系统会把这里统一起来）

- **台词表**（S4-2，`src/lines.js`，第 0 层）：路上、家里人物说的每一句——编号、谁说、几种说法（轮换）、什么情境合适（时段、去／回、下雨、一局只说一次）、气泡样式、爷爷短句的配音类别。**什么时候说由规则定，说什么由表定**：规则层 `sim.speak('编号', 变量)`；邻居、老孙、孙女 `ui.helperLine(谁, '编号')`；挑句是纯函数 `pickLine`（不合情境就不说）。关卡里按剧本走的台词（摊主、驿站老板、裁判、诈骗电话、包饺子）在同一文件的 `SCRIPT`，关卡按顺序读；讲座正文是科普内容，留在关卡里。界面提示与旁白取自 `narr.js`。
- **声音调度**（S4-3，`audio.voice(通道, 配音, 选项)`，所有人声只走这里；`datacheck` 查出别处直接调 `playVoice`）：

  | 通道 | 谁 | 规则 |
  |---|---|---|
  | main | 往事（memory）、犹豫自言自语（moment）、关卡里的人物（game） | 往事、犹豫：停掉别的马上说；关卡：停掉本关上一句，排在做法旁白之后（soft：有人说就不说） |
  | urgent | 爷爷迷路、电话里的话 | 打断闲话与旁白马上说；主戏在说就只留气泡 |
  | chat | 爷爷其他短句、邻居、老孙、孙女、背景人物 | 有人在说就不说 |
  | narr | 朗读提示 | 排在人物后面；新的一条换掉上一条 |

  玩家操作：暂停＝全部挂起、继续接着播；跳过往事、关掉犹豫面板、关卡里点推进按钮（“不对劲！”这类标记按钮除外）、关卡结束＝停掉那一段的话与旁白；打开手册等页面＝全停。犹豫时刻转进它自己的关卡时，那句话接着说完。
- **配音与文字**：`Local/tts/install.py` 写出 `src/voice/texts.json`（每条录音念的文字）；`datacheck` 核对简介、往事、台词、旁白与录音一致；旁白与台词表里该出声的每句都有配音、爷爷短句的配音类别与表一致；代码里用到的台词编号都在表里。配音清单由 `node tools/voicelines.mjs` 按提示表与台词表同步（要重做的旧录音移到 `Local/tts/out/old/`，不删）。
- **自检**：`core.lineLog`（谁、几点、什么场景说了哪句）＋`tools/linerules.mjs`（时间、去／回、下雨、称呼、谁在什么事里说话）；`audio.voiceLog`（每句等了多久才开口，超 1 秒报出）；残留声音（关卡里点了推进按钮、面板关了，上一段的话还在播）；话被掐断（关卡自动关闭时这一步的话没说完——关卡一律“说完再关” `closeAfter`）；都在 `walkcheck` 里跑，三种跑法：不布置、拜托全部邻居、小关卡全做错（`WALK_FAIL=1`，自动试玩故意做错，专测失败分支）（录制工具的声音时钟默认只走开头一段，检查里设 `audioSec: 1000, sr: 8000` 让它走满一整天）。`Local/tts/asrcheck.py` 用语音识别核对录音念得对不对（同音字多，作可选工具）。

| 模块私有 | 各模块 `export let` | 例：`mapops.mapMode`、`flow.eveningOn`、`stage.idleOn` | **只由所在模块改**，别处只读 |

`run` 各字段的主人（只有主人写；别处要改就调主人的函数，读随意）：`speed`→hud（`setSpeed`）；`effSpeed`→main（每帧）；`holdT` `lastMode` `kidHoldUntil` `kidPending` `happyT`→actors（`setKidPending` `cheer`）；`homeAction`→home（`setHomeAction` `tickHomeAction`）；`helpedOnce`→ui（`markHinted` `resetHints`）；`hiking`→bridge；`dayStartPersist`→flow；`tickUI`→overlays；`lineupOn`→devtools。新增字段先定主人，写在这里。

## 3. 初始化顺序

所有模块先加载（此时只定义函数和常量，**顶层不得用到别的模块导出的对象**），然后 `main.js` 按下面顺序调用各模块的 `initXxx()`（都无参数，只为保证顺序）：

`initWorld` → 创建 `sim` → `initBridge`（填回调表）→ `initDevtools` → `initSettingsUi` → `initRoutes` → `initUi` → `initHud` → `initStage` → `initAchieve` → `initHome` → `initMapOps` → `initActors` → `initOverlays` → `initFlow` → `applySettings`、`showTitle`、开始主循环。

`world`、`routes`、`home`、`ui` 等有 `export let`，要等各自的 `initXxx()` 之后才有值；只能在函数里用，不能在模块顶层用。

## 4. 规则层与画面怎么通信

- **画面 → 规则**：直接调 `sim` 的方法（`sim.choose()`、`sim.call()`、`sim.visualArrived()`……）。
- **规则 → 画面**：`sim` 调 `this.h.xxx()`，即 `core.hooks` 回调表，集中在 `bridge.js`（文件头按领域列出每个回调），想知道“规则里的某件事会引起什么反应”只看这一个文件。
- **下层 → 上层**：`core` 的事件机制 `emit(名字, …)`／`on(名字, 处理)`。现有事件：`say`（谁、话、秒：头顶说一句，`ui` 处理）、`neighborGreet`（邻居 id：打招呼，`ui` 处理）、`tellMemory`（讲往事，`flow` 处理）。新增事件写在 `core.js` 的注释和这里。

## 6. 写代码的规矩

1. 新代码放进对应层的模块；单个文件超过约 400 行就考虑拆。
2. 模块之间直接 import，不再往 `initXxx` 里加参数；不许新增循环依赖；import 了就要用上（`modcheck` 查出没用的 import）。
3. 共享状态只由它的“主人”写；新状态先想清楚归谁，写进本页第 2 节。
4. 样式在 `src/styles/`，按文件名顺序拼接（顺序就是层叠顺序，后面的覆盖前面的）；设计表变量在 `1-base.css` 顶部 `:root`，只用变量、不加新的 `!important`。现在是按开发阶段切的 5 个文件，按界面区域重新整理留到画面精修时（有 uidiff 保护）。
5. 剧情与节奏类内容（比如开场）尽量做成数据，放 `data` 层，不写死在流程代码里。
6. **改动流程（10-06 定，用户问“改光影会不会又带出别的问题”）**：① 改前写下可能影响到的地方（哪些系统、哪些天、哪些画面）；② 一般直接在 main 上改、每步本机提交；只有很探索性或很大的改动才另开分支（10-08 用户定）；③ 跑完整检查 `npm run verify`（检查前构建过期会自动重新构建）；④ 所有基准差异（界面截图、3D 画面、性能、规则快照）逐张或逐组看过，在提交说明里写清为什么变，确认是有意的才更新基准；⑤ 部署前看每天的缩略图；⑥ 部署 → 本机 Git 提交 → 更新状态记录（开了分支的先合进 main）。用户发现的新问题，先补能抓住这一类的检查，再改代码。
7. **随机数分三类，不混用**（10-06）：规则层用 sim 自己的带种子随机数；游戏内容（菜摊、包饺子、关卡洗牌）用 `util.contentRand`，每天开始按“第几天、第几次玩”重设种子；纯外观（路人、车、云、落叶、炊烟、飞鸟、环境音、提示语、闪光）各用自己的 `rng(种子)`。不要直接用全局 `Math.random`——按时间触发的效果取了多少次会随帧数变，牵连游戏内容，界面截图比对就不稳。
8. **定规矩的同时定检查**（09-27 复盘：只写在文档里的规矩在赶进度时都被打乱过——没用的 import、绕过 sim 改状态、新加 !important；配了自动检查的分层、存档升级一直守住了）。新规矩能自动查的，就加进 `npm run check`；查不了的，写进下面的审查清单，每个里程碑过一遍。
9. **测试用无头 Chrome 不使用代理网络，直连**（10-07，用户发现 VPN 流量暴增后定）：环境里设了 `HTTPS_PROXY`（Clash），Chrome 会照单使用，测试浏览器的外网流量就全走了 VPN。新建的临时配置目录里，Chrome 运行约 1.5 分钟后会开始下载模型库（约 47MB）、组件包（语音引擎 22MB 等）、安全浏览数据，长时间运行的下到 75—158MB；3 天累计经 Clash 下载 57GB。（实测：直连时前 90 秒配置目录稳定在 13MB，95 秒起增长；3—12 秒的短启动只多约 1MB。所以主要是穿模、回归、画面、缩略图这类跑几分钟的检查在下载；57GB 具体由哪些检查贡献没有逐项量过。）
   **做法**：`tools/chromeflags.mjs` 的 `NO_PROXY_ARGS`＝`--no-proxy-server`（不读环境里的代理，一律直连）；`tools/shot.mjs`、`tools/video/record.mjs`（穿模、画面、缩略图检查都经它）、`tools/package.mjs` 都从这里取。**新增任何启动 Chrome 的地方必须带 `NO_PROXY_ARGS`**，`tools/browsercheck.mjs`（含在 `npm run check`，并守着它不被改弱、不被改成指定代理）会逐处检查；确需走代理或另有写法的，在上一行写 `// browsercheck: allow-proxy 原因`（`package.mjs` 的断网试运行就是：故意把所有请求打到死端口）。实测真实跑 `shot.mjs`：浏览器进程树连 Clash 0 个、游戏页面照常加载。
   **已知代价**：直连不拦下载——长时间运行的测试浏览器仍会从宽带下载（国内直连 Google 的 `optimizationguide-pa`、`clients2` 等 4 个域名会超时、`gvt1.com` 组件包能通；超时在后台线程，实测不拖慢测试：同一步骤 3.07 秒，与拦截时一样），只是不再走 VPN。若宽带流量也要省，在 `NO_PROXY_ARGS` 里加 `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE localhost, EXCLUDE 127.0.0.1`（除本机外域名解析失败，实测零外连）。
   **流量又不对时怎么查**：① 看代理软件的连接统计，按“进程、目的主机”汇总（Clash 的控制套接字 `/connections`，会列出各连接的下载、上传字节），先分清是 Claude 桌面端、测试浏览器还是别的；② 测试浏览器看 `/tmp/mg-chrome-*` 各目录大小——超过几十 MB 说明它在下载；③ 对账：下载总量 ÷ 单次长时间启动的代价 ≈ 长启动次数。不选的替代办法：复用固定配置目录（并行时同一目录第二个 Chrome 会立刻退出；带状态；启动用时实测没有差别）、用本机 Chrome 的配置（含登录与扩展，且被正在用的 Chrome 占着锁）、业界常用的“关后台服务”参数（实测 Chrome 155 里仍会去访问 6 个 Google 主机，拦不全）。
10. **临时 3D 物体收起时要释放显存**（10-10 稳定性审查）：路线、地图连线、路障、路标这类每天或每次点按都会重建的物体，用 `util.disposeTree(物体)`／`util.clearGroup(组, 共用几何体)` 收起，不要只 `scene.remove`／`group.clear()`——只移出场景不释放，几何体和材质一直占着显存（查出指路地图每画一次漏 24 个显存缓冲，玩一周会越积越多）。共用的几何体（`dotGeo`、`arrowGeo`）作为 keep 传入；贴图都是共用的，不释放。

**审查清单（每个里程碑）**：分层与循环（modcheck）；没用的 import（modcheck）；sim 状态只由 sim 改、任务图示齐全（datacheck）；run 字段主人（第 2 节表）；所有人声经 audio.voice、台词进台词表；新样式只用设计表变量、不加 !important；单文件超过约 400 行考虑拆；没人用的导出与死样式；测试工具默认值（跳过开场等）；画面精度（贴图是否随镜头放大会糊）。

## 7. 开发经验：先建统一的层（10-05 总结情境系统与地基）

| 经验 | 来源 |
|---|---|
| **同一类问题在不同地方反复出现，说明缺一个统一的层**：停下补丁，先建这一层，再做新内容 | 情境系统（09-26：场景判断散在各处 → 事件流、台词表、声音调度）；人车穿模（09-29 补丁互相打架 → 地基方案） |
| **一个来源、一个入口、一张表**：信息只有一个来源（如 `sim.ctx()`）；同类动作只走一个入口（如 `audio.voice`）；内容写成声明式的表（如 `lines.js`），规则只决定“什么时候” | 情境系统 |
| **检查和系统同时建**：快、进日常检查、含随机玩家操作；验收写成“故意写错能报出” | 无头情境自检 210 局 0.2 秒 |
| **先在行为不变的前提下迁移，再改行为**：每步对照规则快照、界面像素 | S4 各步、R1—R7 拆模块 |
| **检查看玩家实际看到、听到的东西，不留豁免**：替代指标和特例放行会变成盲区 | 气泡跨天、健步走穿墙都是用户看视频发现的；走路检查对社区中心周围的人群一律放行 |
| **系统性改动不在截止前做**：在分支上做，检查全过、用户试玩后再合并 | 09-29 晚的车人补丁（见地基方案二） |

统一层的范围也要想全：情境系统统一了“时间、事件、说话”，没包括画面层的空间，后来的问题就出在那里。新建一层时先列清它管什么、不管什么，不管的部分由谁管。

**10-06 动法统一的教训**：只统一“能走在哪”不够，还要统一“怎么动”；检查要能看见“动法”（速度、朝向、跟随、互相等），不能只看位置；画面跟不上时让时钟等画面，不让画面冲刺；任何“等”都先想对方会不会也在等我；检查前先重新构建，数字过了还要看录像。

**10-07 匀速的教训**：用户说“到路口一顿”，检查先要能量出来（顿挫、急刹），再给每个样本记“当时在做什么”，原因一下就清楚——街角目标点被夹住、到点就停、走到跟前才刹。动的东西都按“目标速度＋加减速上限＋刹得住的距离”走，而不是“走到目标点就站住”。检查的计时要和被检查的东西用同一个钟。

## 画面精度（09-27，阴影毛刺之后定）

- 几何体（房屋、道路、人物、树）每帧按屏幕分辨率重画，放大不糊；**贴图**（阴影贴图、程序画的雾／日月／老照片）格数固定，放大会糊或起锯齿。
- 规则：会被镜头拉近看的贴图，精度要跟着镜头走。阴影贴图的范围按镜头远近收放、中心按格对齐（main.js updateLighting）；程序画的贴图统一用 `util.canvasTexture`（画完即存像素，防浏览器清空画布）。
- 画质档（world.js GFX）：清晰度倍数 1／1.5／2、阴影 0／1024／2048 格——为性能有意取舍，“流畅”档在高分屏上会略软。
- 新加贴图时先问：镜头最近时它在屏幕上多大？贴图格数至少要和那时的屏幕像素相当，或者本身就是柔边（雾、光晕）。
