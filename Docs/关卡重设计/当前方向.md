## 一、已定的根（用户 10-11—10-12 逐条定，详见设计基石）

| 层 | 决定 |
|---|---|
| 为什么做 | 让家属看得见他在变，也帮得对：分得清是老了还是病了，帮得刚好、不替他过日子 |
| 带走什么 | **早发现**：这些变化是信号，该陪他去看医生了。和“帮他过日子”并列。游戏里不出现就医，“该陪他去看看”放在结尾和「记忆」页 |
| 给谁 | 家里老人刚有变化、还没看过医生的成年子女和孙辈（约 20—50 岁）为主；迟早会遇到的普通年轻人为次要 |
| 核心体验 | 你是他身边的人。平时帮他过日子：帮少了出事，帮多了伤他的自尊、让他更依赖，后果带到第二天。他的变化一天天出现在日子里。一周结束时回看，分清偶尔忘事和一直在、越来越影响生活的变化 |
| 帮与看 | **不绑定**：帮多少的理由是他的自尊和依赖；家属没资格评估症状，评估交给医生 |
| 回看放哪 | 不进剧情，放在现有的「一周总结」里 |
| 底子 | 以现有游戏为底：布置 → 看他出门 → 当下帮 → 往事 → 结算 |
| 小关卡 | 去掉六道考题关（菜单、找零、取件码、连线、修闹钟、摆残局，事情照常发生）；保留包饺子、诈骗电话（按反诈调整）、电话指路；**每天都要有关卡，要有趣味和难度** |
| 新关卡 | 既考帮的人的本事，也让玩家认识症状 |
| 症状怎么讲 | 第 3 天讲座保留原内容；讲座、结算、关卡多处强调，最后再总结，不算重复（10-12） |
| 核心原则 | 三层：①价值目标 ②核心体验（含跨天后果）③手段放开——判断标准是“会不会改变玩家接下来怎么帮”（10-10） |

## 二、走过的弯路：否定的做法与原因

这些都试过或写过，被用户否定或证明不通。**以后提方案先对照这一节。**

| 做法 | 为什么不行 | 出处 |
|---|---|---|
| 小关卡做成量表考题（玩家替他答题） | 难的是玩家自己的记性，不是他；玩家答对还被记成“他自己办的”；家属等于在给他做测验 | 调研/现有系统梳理 第三节 |
| 玩家整关扮演他（第一人称找钥匙、走回家、饭桌…） | 与核心体验“你是他身边的人”不符；体验完不接一个帮的决定 | 调研/短片与真实困境 第三—六节 |
| 白天随时进他眼里看他缺哪块（距离梯子） | 像透视：家属看不见他心里，帮得太容易、也不真实 | 归档/视角统一设计 |
| 帮多少和认识症状绑在一起（帮太多会盖住信号、在关卡里看他错几次） | 家属没资格评估症状（用户 10-11） | 设计基石 |
| 另办“认知友好体验馆”活动来放解谜 | 不够自然，要融进整体游戏（用户 10-12） | — |
| “找”的原型（2D 静态图、点三处、出文字） | **用户 10-13：没有价值、一点意思都没有、和主框架没关系、点来点去的文字操作**。退化成了 AGENTS 早就禁止的“静态图文、只靠对白选项”；没用上游戏最大的资产：3D 小镇、雾、他这个人 | 原型已删（next 同步 main 时去掉） |
| 设计稿一份接一份推翻 | 底层没定就设计上层，每份稿暗含不同的根 | 本次整理 |

**由此定下的做事规矩**：先定根再定关、一次一问；原型做**最有游戏性**的，不做最省事的；关卡必须用游戏现有的 3D 世界、雾和他，不另起 2D 文字面板；纸面好玩不等于真好玩，原型要真人试玩。

## 三、主线候选：雾里的解谜（短片的六个房间）

**状态**：10-13 提出；用户 10-14 同意按“整理文档 → 讨论清楚 → 先做碎镜子”的顺序推进。**作为主线候选，具体剧情与关卡待第七节讨论后定。**

**融合思路**：短片里的“认知友好环境实验室”，是把症状做成人能走进去的空间；游戏里的雾，是他心里不确定的地方——两者是同一件事。**他在小镇上卡住时，雾里的那一块变成短片里的一个房间，成为一道 3D 解谜；你解开它，就是陪他一起想、帮他认了出来，雾当场散开。**

**接上现有系统**
- 犹豫时刻里“陪他一起想”（`MOMENTS` 里的 `cue.game`）原本打开 2D 考题，改成打开 3D 解谜。
- 解开后用现有的“今天认得这个路口”（`learnNode`）：雾当场散；第二天雾又回来（近事记不牢，现有规则）。
- 画面、人物、镜头、灯光、日照都用现有 3D。

| 短片的房间 | 可能放在哪个剧情点 | 3D 解谜 | 症状就是规则 | 解开后 |
|---|---|---|---|---|
| 碎镜子 | 第 4 天老电影院（已改成手机店）认不出 | 玻璃碎片浮在空中，转镜头找到**他记忆里的角度**，碎片拼成当年的门脸（视角对齐） | 熟悉的地方变了样就认不出；他心里存的是旧样子 | 认出来，雾散，接着讲和老伴看电影的往事 |
| 挂钟墙 | 第 3 天早上以为是星期六；第 4 天要准时出门 | 一墙数字反写、乱序的钟；真时间从**窗外太阳的影子**（日照随时间走）、电视节目、送奶车推出来 | 看钟、弄清时间变吃力；他认得太阳和老作息 | 拨对大钟，他自己说“哦，星期四” |
| 推不开的门 | 第 1 天早上出门 | 一层套一层的门框，推、拉、不开，走廊会绕回原地；跟着**他认得的老东西**才走得出去 | 知道门在哪，却不知道怎么出去 | 他自己出门，准时去下棋 |
| 深坑地垫 | 第 4 天夜里看完电影回家 | 夜里几块深色地方像坑又像垫；**移动灯光**（路灯光锥、手电）看阴影，分出哪块是平的，铺出一条路 | 看远近深浅变难；光线和对比色有用 | 他踩着亮处到家；你知道了门口该换浅色地垫 |
| 晃眼的条纹走廊 | 人多的菜市场慌了（现有：人多处慌得快） | 街道起波纹、颜色乱跳、叫卖声叠在一起；**关掉噪声**，把他的视线**稳在老地标**上 | 慌了以后什么都看不清、听不清 | 他平静下来（现有 `anxiety` 下降） |
| 翻牌墙 | 一周结束、一周总结之前 | 他家墙上的翻牌做 3D 记忆配对：正面家人常说的话，背面他的日记；正面会出现**你这一周真的说过的话** | 那些话他听在心里是什么滋味 | 接进一周总结和结局 |

**边界**：开头一句交代这是他心里的雾、是比喻，不说“他眼睛看到的就是这样”；不吓人（不闪烁、不恐怖扭曲，配色与雾一致）；每关解开后一句话对上现实里的样子。

**可行性（按代码）**：视角对齐、阴影推理、移动光源、传送式循环走廊、3D 翻牌，都是 Three.js 常规做法；云端软件渲染能截 3D 图自查，手感由本机看、用户试玩。

## 六、要守的边界（不变）

不诊断、不打分、不输出风险；不测玩家；他始终是有主见、能干的人；玩家失误不导致病情进展；不将记忆混淆直接等同幻觉；强失真只作比喻、不吓人；不承诺训练或筛查效果。

## 七、接下来要讨论清楚的问题（暂不开发）

按依赖顺序，一次一问，结论记进设计基石：

1. **每天的关卡由什么组成**：一天一个解谜？解谜加一个帮的关卡？还是有的天是解谜、有的天是帮？（已定：每天都要有关卡）
   - 10-14 已提给用户（用户暂未定，之后再讨论）：A 每天一道解谜；B 每天解谜＋帮的关卡（最丰富，但每天变长，现整局约 30—40 分钟）；C 按天交替，解谜只需三四个房间。助手建议 C（理解他与学会帮交替，保住包饺子、反诈、指路），**不是用户定案**。
2. **六个房间放在哪几天、哪个剧情点**：七天对六个房间；第 5 天包饺子、第 6 天反诈电话怎么排。
3. **解谜里玩家是谁、怎么说**：“他心里的雾、你陪他想”这一层比喻用什么方式交代（开场一次？每次一句？）。
4. **解开与没解开的后果**：散雾、算不算“他自己办的”、心情、跨天后果。
5. **剧情要改多少**：七天的事、时间、往事、人物（老李会计身份、孙女、邻居）哪些保留、哪些要为新关卡改。
6. **早发现这条线**：解谜后的一句话、讲座、结算、一周总结回看，怎么串成一条线。
7. **帮的关卡（候选七个）还要不要**、和解谜怎么分工。
8. **晚上“记”（拼老照片）要不要**。
9. **反诈那天**怎么改（约定卡、只能提醒一句、事后怎么接）。
10. **分寸**：碎镜子、深坑、条纹这些强失真的比喻，用到什么程度。
