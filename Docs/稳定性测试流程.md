# 稳定性测试流程

10-14 定（用户：游戏的稳定性是基础，不容让步，值得充分投入测试，建立标准测试流程）。这份文档说什么时候测、测什么、合格线是多少、不合格怎么办。各项检查工具的细节见 [架构](./架构.md) 第 5 节。

## 一、什么时候跑什么

| 时机 | 跑什么 | 大约多久 |
|---|---|---|
| 每次改代码 | `npm run check` | 几秒 |
| 看得见的改动 | `npm run verify` | 约 15 分钟 |
| 改了每帧逻辑、镜头、走路寻路、加载方式 | `npm run stability`（可只跑相关的一项：`-- --only rotate`） | 一项 2—10 分钟 |
| 发布之前：小修（某一关的逻辑、文字、样式，不碰每帧画面、镜头、走路、加载） | `npm run check`，加一个专门测这处改动的测试（最好先在旧版上复现问题） | 几分钟 |
| 发布之前：改了每帧画面、镜头、走路、加载，或大版本上线 | `npm run verify -- --full`，再跑 `npm run stability` 全套，逐天看缩略图 | 约 50 分钟 |

10-15 用户同意分档：小修不必跑全套（全套一次 35 分钟左右，大头是按真实时间把一周玩两遍）。

同一台机器同时只跑一套稳定性测试：两套一起跑，帧率会互相拖累（10-14 实测，Mac 模拟的帧率从 60 掉到 49）。`verify` 自己会开两个浏览器，也别和 `stability` 同时跑。

## 二、稳定性测试测什么（`tools/stability/run.mjs`）

按真实时间跑（不用录视频的虚拟时间，测出来的卡顿就是玩家看到的卡顿），用显卡渲染，测试浏览器不走代理。

| 项 | 模拟什么 | 怎么测 | 合格线 |
|---|---|---|---|
| 启动 | 手机：CPU 慢 4 倍、网速 10Mbps、延迟 60ms，gzip 传输，和线上一样 | 打开页面到标题按钮出现、配音到齐，3 次取中间值 | 标题 ≤ 1.5 秒，配音 ≤ 10 秒 |
| 旋转 | 手机慢 4 倍、慢 8 倍；Mac（1440×900、2 倍屏）慢 2 倍 | 进第 1 天，他出门走在路上时：静止 4 秒，再来回旋转 4 次（手机用两指横扫，电脑用右键拖） | 测量时没有超过 100ms 的帧；每帧主线程工作量的 95 分位 ≤ 33ms |
| 抢镜头 | Mac，暂停后他站着不动 | 压低镜头，拖转 30° 后按住 3 秒再松手，转一圈共 12 次 | 按住时被自动视角转走 0 次，松手被拽回 0 次 |
| 连玩 7 天 | Mac 慢 2 倍、手机慢 4 倍 | 自动玩家（`tools/video/play.mjs`）把一周玩完，每天记帧率、长帧、换天耗时、页面报错、玩完时的内存 | 7 天都玩完；页面报错 0；第 7 天内存不超过第 1 天的 1.5 倍；超过 250ms 的帧一周不超过 20 个；换天 ≤ 3 秒 |

合格线写在 `run.mjs` 开头的 `LIMITS`。它是“慢手机上也不能卡”的底线，不是目标；要改线，先确认测试机没有别的任务在跑，再在提交说明里写清原因。

结果在 `Game/snapshots/stability/<时间>/`：`summary.md` 是给人看的对照表，`result.json`（被测版本）、`base.json`（对照版本）是全部数字，长帧带着发生时的游戏状态（几点、他在做什么、几倍速），能直接看出卡在哪一步。

## 三、不合格了怎么办

1. 先看 `summary.md` 里长帧发生时的状态，判断是哪一段（出门、找角度、换天、关卡）。
2. 用 CPU 剖面找到具体的函数：照 `tools/stability/rt.mjs` 起浏览器，构建时把 `build.mjs` 里的 `minify` 改成 `false`（只在临时目录里改），在出问题的那段用 DevTools 的 `Profiler.start／stop` 抓 4—8 秒，按函数汇总自身耗时和包含耗时。10-14 就是这样查到 `nearestEdge` 占了 77%。
3. 修完先跑 `npm run check`，再跑不合格的那一项，最后部署前全套再跑一遍。
4. 用户发现的新卡顿：先把这种情况加进稳定性测试，能测出来了再修。

## 四、它测不到的

- 显卡：测试机是独立显卡，手机和 Mac 的显卡慢多少模拟不了，只能模拟 CPU。显卡吃紧时靠动态分辨率降像素（`world.js` `dynRes`）。真机上卡，先在真机 Chrome 的性能面板看是 CPU 还是 GPU。
- 真机触屏手感：两指旋转、拖动只模拟了手势本身。
- Safari：测试用的是 Chrome。

所以部署后还要在真机上看一眼：演示用的 Mac（Chrome）和手机，各转几下地图、走完第 1 天出门那一段。
