更新：2026-10-05｜linux-b / Claude Code（claude-opus-5-5）。初赛后阶段 1“地基”（P0）的方案。合并了 next 分支 09-29 晚的尝试与教训。

## 〇、范围：管什么、不管什么

地基是**空间与移动的统一层**——画面里谁在哪、怎么走、和谁怎么让，都由它管。交通规则只是其中一项。

**管**
1. **空间的唯一来源（可行走地图）**：路面（路段与路口方块）、人行道、过街区域、门口通道、屋里、广场、建筑外形；谁能在哪里（人、车各自的区域）。
2. **统一移动**：所有会动的——爷爷的画面位置（路上、进出门、家里、被接回家）、陪同的你、孙女、健步走队伍、看电影与比赛的人群、棋友、邻居、老孙、路人、车、开场脚本里的人。
3. **相互作用**：人车让行与完整交通规则；人与人不重叠（队伍间距、并排、擦肩）；过街；被堵转身或改道；僵持兜底。
4. **规则层到画面层的映射**：规则层只管“在哪两个路口之间”；画面位置由地基映射到合法位置，不再随手加偏移。
5. **画面状态的生命周期**：每天开始重置路人、车、人群、门、头顶的话；跨天、跨场景不残留。
6. **检查与调试**：独立于地基本身（用场景里的实际外形）、无豁免、多种子×多倍速×三种走法；调试画面显示可行走区域与每个角色的状态；修好“行尾注释吞代码”检查。
7. **顺带核对**：身高调整后的站位（棋亭座位、陪同间距、孙女牵手）。

**不管（由谁管）**
- 规则层的走路、犹豫、迷路、拐错（walk.js，地基不改，规则快照不变）。
- 台词与声音（情境系统）；镜头（camera.js）；界面排版（layoutcheck）；光影与画面精度（画面与光影）。

## 一、为什么一直修不好

1. **“哪里能走”没有唯一的答案**：能走的地方由道路图、门口进出路线、屋里站位和各种特例拼出来；房子是小镇生成时摆的，移动时没有任何代码查“这里有没有房子”。走路检查也只是“离路多远”的近似，还带豁免（健步走穿墙就是被“社区中心周围 6.5 米内的人群一律放行”漏掉的）。
2. **移动写在十来个地方，各写各的**：爷爷（跟随规则层位置；进出门、家里各有路线）、陪同的你和孙女（按固定偏移跟着爷爷）、健步走队伍（直线追前一个人）、邻居（沿路寻路）、路人和车（各按车道偏移）、开场（脚本）。每多一种移动方式就多一种穿墙的可能。
3. **规则层和画面层两套坐标**：规则层只知道“他在哪两个路口之间”，画面层再加偏移、平滑、跟随，没人检查这些会不会出界。
4. **人车互动是一对一的临时规则**：每条规则单独看都对，合起来会互相等。
5. **检查有盲区、截止前补丁**：只覆盖自动玩到的路线，有容差和豁免；看到一个现象补一处，补丁之间打架。

## 三、一般游戏项目的做法

1. **一份可行走区域数据，所有东西都用它**：3D 游戏常用导航网格（如 Recast/Detour），俯视类常用“占用地图”（地面分格，标路、人行道、房子、屋里）。寻路、移动、检查都查这一份。
2. **移动必须经过统一入口**：角色只说“我想往这走”，由移动系统决定实际走到哪；碰到不能走的地方就沿边滑开或停下。
3. **跟随者沿路径走**：跟领头人的足迹，或在同一张地图上自己寻路。
4. **交通靠分区和优先级**：车只在车道，人只在人行道，只在过街区域交汇；交汇时行人优先，过街区域一次只让一方进入（“占用”），从结构上避免互相等。很多游戏直接简化：车少、只走外圈、主角附近不出车。
5. **不变量检查与可视化**：每帧断言“没人在不能走的地方、人车不重叠、没人卡住超过几秒”；多种子、多倍速长时间跑；调试画面把可行走区域和每个角色的状态画出来。
6. **检查独立于被检查的系统**：检查不能和移动共用同一份可能出错的数据，应直接用场景里房子、路面的实际外形。

## 四、设计依据：情境系统的经验（09-26）

**背景**：09-26 第十四轮试玩，分层和模块已稳定，但“几点、在哪、谁、刚发生了什么、玩家做了什么”散在各处，台词、配音、时间、迷雾各自判断场景，于是各自出错（王阿姨中午说“天快黑了”、倍速讲往事没声音、关卡点了确认话还在播、后门出来先到路口再折回）。用户定：先把情境系统做好，再做新内容。

**做法（S4-1—S4-5）**：事件流（每件事带同一份情境 `sim.ctx()`）、台词表（`lines.js`，什么时候说由规则定、说什么由表定）、声音调度（所有人声只走 `audio.voice` 一个入口，分通道与优先级）、无头自检（7 天×多种玩法×随机玩家操作，210 局 0.2 秒，进 `npm run check`）、定版后给用户试玩重点。

**改善**：第十五轮反馈多是内容层面（台词顺序、音色、多音字），场景判断错明显变少；之后同类问题一处修全并配检查（如同一人 60 分钟内不重复同一句、每天开始收起所有人头上的话）；开场、他的地图、他打来的电话、心情分类、往事按结果挑都直接建在事件流上；初赛前大量改动时场景类错误没有大面积回来。

**局限**：只统一了“时间、事件、说话”，**画面层的空间（人站在哪、走哪条路、会不会穿房子或车）没有包括进去**——正是后来穿模反复出现的地方；它的检查查的是事件与台词，看不到画面（气泡跨天、穿墙只能靠用户看视频发现）。

**地基就是“空间的情境系统”**：

| 情境系统（时间与说话） | 地基（空间与移动） |
|---|---|
| 情境只有一个来源（事件流 `sim.ctx()`） | 可行走区域只有一个来源（可行走地图） |
| 说话只走一个入口（`audio.voice`） | 移动只走一个入口（统一移动） |
| 通道与优先级（谁能打断谁） | 交通规则（谁让谁、过街区域一次一方） |
| 台词表（声明式） | 区域与车道（声明式，从小镇生成结果建出） |
| 无头自检＋随机玩家操作 | 不变量检查，多种子、多倍速、三种走法 |

**照搬的做法**
1. 同一类问题在不同地方反复出现＝缺一个统一的层：停下补丁，先建这一层。
2. 检查和系统同时建，要快、进日常检查；验收写成“故意写错能报出”，不是“跑一遍没报错”。
3. 先在行为不变的前提下迁移，再改行为（S4 每步要求规则快照不变、界面像素一致；地基一次迁一种角色、每迁一种跑检查）。
4. 检查看玩家实际看到、听到的东西，不用替代指标，不留豁免。
5. 在新内容之前做，不在截止前做。

## 七、进度

**第一步 检查与调试画面（10-05 完成，分支 foundation）**
- 实体外形表 `town.solids`：小镇合并网格前，从每个实体网格的包围盒算出地面上的四个角（世界坐标；邻居家斜放也准）。实体：房子墙体、树干、路灯杆、老电影院、水井、菜摊、棋亭柱子与棋桌、家里的墙；能进去的楼（药店、驿站、社区中心）标 enterable，只许爷爷进。
- 检查（walkcheck，每 0.1 秒）新增：进墙、人叠人（中心不到 0.3）；移植 next：车出路面（路段宽 3.2＋路口 3.2 见方）、车僵住（停 12 秒以上）、路人僵住（不歇脚 10 秒没挪窝）、车穿人记人名与车速。只加记录，不改任何移动行为（check 全过、规则快照不变）。
- 修好“行尾注释吞语句”检查（datacheck），故意写错能报出；next 上那处能被抓到。
- 调试画面：`__mg.space(true)` 画出实体外形（红；能进的楼橙）与路口方块（灰）。

**第二步 量路边、腾出人行道（10-05 完成）**
- `space.sideClearance`：每段路每一侧，从路面边往外到最近实体的宽度。第一次量：一半路边只有 1.6—2.0（房子墙、路灯杆、树干压在浅色人行道上）——09-29 把爷爷挪到 1.9 就进墙的根因。
- 布局微调（暂定；随机数照取、街区布局不变）：小房子最宽 3.4（原 3.8）、街区内位置 ±2.0（原 ±2.2）；路灯 2.2（原 2.1，且不再插进房子）；老电影院、老榕树往街区里挪、树根台缩小；邻居家往里收 1；公园树圈 3.2；家门口的树不摆；外圈树离路 4 以外；邻居日常站在自家门前。
- 自检：`space.solidOverlaps`（实体互相重叠，分离轴）＝0；每段路两侧通行宽度都 ≥1.95。

**第二步续：可行走地图的设计（10-05 定，按此实现）**
- 尺寸：路面半宽 1.6；车道中心离路中线 0.8（车宽 1.5，外沿 1.55）；**人走在离路中线 1.9 的人行线上**（离车 0.2，离房子墙 ≥0.25，离路灯杆留出身体宽）。
- 人行网：每个路口四个角点（±1.9, ±1.9）；同一侧相邻路口的角点相连（人行道）；同一路口相邻角点相连——中间有路的那一段是**过街**（斑马线位置，路口方块外侧），没有路的（地图边上）直接绕过。门：地点的门口通道（路边→门前→门→屋里）接到它那一侧的人行线上；邻居家门、家门同理。
- 人不分靠左靠右，按最少过街走：沿一侧走到路口，下一段路在同侧就不过街，否则过一次。
- 爷爷：规则层不动；画面里沿人行网追规则层的位置——规则层走一段路（路口 a→b），画面就排一串路点（当前角点 →〔过街〕→ b 那头同侧的角点），按“同时到达”的速度走；规则层停（犹豫）画面就停在角点；掉头就在同一侧往回走；进门出门从人行线接门口通道（在对面就先过街）。
- 跟随的人（陪同的你、孙女、健步走队伍）沿爷爷画面里的足迹走；邻居、被接回家沿人行网寻路；路人在人行网上随机走。
- 车：只在车道；进路口先开到路口中心再原地转（车身转动半径 1.59 ≤ 1.6）。
- 过街区域与路口方块各是一个“占用区”：一次只让一方（人或车）进入；人先到人先走，车让人；被堵 3 秒的人转身或改道，车等 5 秒掉头。每天开始重置路人、车。

**第三、四步 统一移动与完整交通规则（10-05—10-06 完成，分支 foundation）**
- 可行走地图 `space.js`：路口四角＋人行道＋过街（126 处）＋各门接入（地点门、后门、邻居家门、家门）；`path` 寻路（过街多算 4，能不过就不过；终点不在网上就停在网上最近的一点）；`isWalkable`（离人行网 0.45 以内或在空地里）、`canStand`（再加不碰任何实体）、`snap`；自检全部连通、离实体都留出身体宽。社区中心门前空地（看电影、比赛的人群站在这里，让出进门那条路）。
- 统一移动入口 `mover.js`：`stepTo`／`stepAlong`（过街前问让行）、`separate`（人与人分离：推前先看能不能站，不推爷爷）。家里、进出门、开场、邻居、跟随的人都经它。
- 爷爷：规则层不动；画面按规则层位置在人行线上追，换路段按少过街选边，过街走斑马线，稍靠右（迎面错开 0.36），前面有人画面里先等（≤4 秒）；进门出门、出入家门走门口连线；开场也走人行道。

**第五步 动法统一（10-06，分支 motion；用户：“越改问题越多，从根源上解决”）**

起因：地基合进 main 后用户又看到三处——车直行像 S 形横着挪、健步走爷爷走了很久队伍才快跑跟出来、接孙女时孙女跟不上；修车时又带出车出路面、车僵住。根源有三条：
1. **检查只查“站的位置”，不查“动得对不对”**：横移、冲刺、掉队、互相等全都放行，只能靠用户试玩发现。
2. **各角色各写一套“怎么动”**：爷爷、跟随的人、车都有自己的“落后多少就快多少”，规则层和画面靠画面冲刺对齐；改一处，别处冒出瞬移、冲刺、横移。
3. **验收不严**：一次检查用的是旧构建（没重新构建），一次只看数字没看画面。

**定下的动法规矩**（对所有会动的人和车一样）：
- 画面里的人只经 `mover.stepTo`／`stepAlong` 挪：起步平滑、朝向跟着走、不许“落后多少就快多少”。
- 画面速度从规则层此刻的速度算（`sim.walkRate`：健步走、迷路、下雨、赶时间都算）×倍速×1.3——从设计上跟得上。
- 画面落后 6 以上（或跟着的人掉队）：**整个时钟停一下**等画面（`sim.setVisualLag`，只有画面层会设），画面的等待不占游戏时间，真实游戏与模拟、快照结果一致；一次最多停 8 秒。
- 跟随＝面包屑：记住自己走到第几个足迹点，只往前；在他身边先站着；离得远沿人行网走；只让排在自己前面的人。
- 看得见的人不瞬移；直线走不过去就沿人行网寻路；寻路起止点只吸附人行道（不吸到斑马线上）；站在马路上的人先走完、不在路中间等车。
- 过街让车对所有人一样（`stepAlong` 默认问）；人在路边等着过街时，停车线前的车先让（行人优先）。
- 车：不掉头（路网没有死胡同，3.2 宽的路上掉头必压出路面）；过路口沿三次贝塞尔（直行不离车道、右转 3.1、左转 3.8，离线验证车身四角全程在路面上）；车身缩一成（2.5×1.36）；只让真站在路面上的人、同方向的前车；路口里遇人立刻停。
- 一天收尾等画面里的他和跟着的人都进了家门。

**检查补强**（walkcheck，无豁免）：冲刺、横移（人、车）、掉队、不跟、互相等、画面卡住、时钟为等画面停了多少秒（每天上限 30）；源码比构建新就先重新构建。改前基线：车横移每天上千次、爷爷冲刺、健步走队伍掉队 32。
